# Петрович.BRO: правила для ИИ-ассистента

Этот файл читается в начале каждой сессии. Здесь только главное: жёсткие правила и карта документов.
Подробности лежат в `docs/`, их читаем по мере надобности.

## Продукт в двух словах
Петрович.BRO: бесплатный сервис для управления ремонтом и строительством.
Профессионалы ведут объекты от замера до акта: сметы из шаблонов и калькулятора с ценами Петровича, план-график, финансы, документы, команда.
Заказчик получает доступ к объекту и сам следит за сметой, сроками и расходами.
Основная аудитория: профессионалы. Новая аудитория: заказчики ремонта (они могут привести бригаду в сервис).
Подробно: `docs/product/overview.md`, `docs/product/roles.md`.

## Жёсткие правила

### Тексты
- Не используем длинное и среднее тире («—», «–») и точку-разделитель «·». Вместо них: двоеточие, запятая, точка, перенос строки.
- Обращение на «вы» с маленькой буквы. Никаких «ты».
- Коротко и по делу. Сначала польза для пользователя, потом функция.
- Подробно: `docs/design/copy.md`.

### Интерфейс и макеты
- Экраны продукта берём только из реальных макетов Figma (`docs/design/figma-map.md`). Не придумываем свои экраны, иконки, структуру сайдбара или таблиц.
- Если для анимации нужен экран, которого нет в макетах, спрашиваем, а не рисуем сами.
- Кнопки только из кита (набор `Button`, вариант `radius=square`, r8, Semibold). Иконки только из «UI-kit BRO App» (`h-icon/outline/*`).
- Стили текста и цвета только из токенов v4 (`docs/design/tokens.md`). Новые значения не вводим без согласования.
- Сетка лендинга 1920, поля 96, контейнер 1728. Фоны полос тянутся на всю ширину окна.

### Данные
- Во всех экранах, плашках и цифрах одни и те же демо-данные: `docs/product/demo-data.md`.
- Суммы не придумываем: считаем из позиций сметы.

### Безопасность
- Продакшн bro.petrovich.ru только на чтение: открывать и смотреть, ничего не создавать, не менять, не удалять.
- Никогда не удалять аккаунт пользователя и его данные.
- Логины, пароли, токены не пишем в репозиторий, документы и сообщения коммитов.
- Файлы шрифта SF Pro не коммитим (лицензия). Сборки со встроенным шрифтом держим только локально.

## Как работаем
1. Новая задача начинается с брифа: `docs/briefs/_template.md`. Если чего-то нет, спрашиваем.
2. Сначала план, потом выполнение. Спорное и вкусовое уточняем вопросом, а не додумываем.
3. Figma: правки делаем в дубле, старое не удаляем, а скрываем с пометкой «(старый, скрыт)» для отката.
4. После правок проверяем: скриншот, нет запрещённых символов, нет обрезанного текста и наложений.
5. Код: ветка `claude/petrovich-bro-design-spxj37`, понятные сообщения коммитов на русском.
6. Каждая поправка дизайнера становится правилом в этом файле или в `docs/`, чтобы не повторять ошибку.
